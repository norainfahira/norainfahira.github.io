SECP2613 - System Analysis and Design (WBL)

Credit Hours : 3

Lecturer : Dr. Aryati binti Bakri

Section : 01

Course Description

This course focuses on transforming real-world problems into practical information systems. It covers analyzing system requirements, designing solutions, and developing fully functional database applications. From planning to implementation, students gain hands-on experience in creating systems that operate effectively within real organizations.

Assignments

Assignment 1 : Project Planning and Feasibilty StudyCompleted

This assignment required a feasibility study and project planning analysis for a clinic appointment and patient queue management system. The case study was based on a real clinic scenario where manual methods (phone calls, WhatsApp, paper books, Excel files) were still being used to manage patient appointments. The tasks included defining current problems, listing project objectives and system requirements, analyzing technical, operational, and economic feasibility, performing a 3-year cost-benefit analysis using Present Value (PV) and Profitability Index (PI), and delivering a final recommendation on whether the project should proceed. This assignment contributes 5% to the continuous assesment.

Assignment 2 : Data Flow DiagramCompleted

This assignment requires students to read a given case study about a hospital system and then produce three Data Flow Diagrams: a context diagram, a Diagram 0, and one Level 1 diagram. Students need to identify external entities, processes, data flows, and data stores based on the system description provided. This assignment contributes 5% to the continuous assesment.

Project

Phase 1 – Project Proposal and PlanningIn progress

The company background is studied to understand what problems they have. Then the problem is written down clearly and a new system is suggested to fix it. The objectives and scope are also set – what will be done and what will not be done. After that, a feasibility study is done to check if the project is possible from three sides: technical, operational, and economic. A simple cost-benefit analysis is also included. Finally, a project plan is made. This includes a WBS (list of tasks), a PERT chart (showing task order), and a Gantt chart (a bar chart for the timeline). This phase contributes 11% to the total project mark.

Phase 2 – Information Gathering and Requirement AnalysisIn progress

Information about the current system is collected using methods like interviews or questionnaires. Some example questions must be shown, and a short summary of the answers must be written. Then the current business process is analysed. The functional requirements (input, process, output) and non-functional requirements (performance, security) are listed down. After that, logical DFDs are drawn to show how data moves in the current system. This includes a context diagram (big picture), diagram 0 (main processes), and a child diagram if needed. This phase contributes 11% to the total project mark.

Phase 3 – Analysis and System DesignPending

The new system is designed here. First, logical DFDs for the new system (TO-BE) are drawn – context diagram, diagram 0, and child diagrams. Then the physical design is done, showing which parts are done by computer and which are done manually. A CRUD matrix, event response table, structure chart, and system architecture are also created. Finally, a simple non-working prototype is designed – just the screens and layout. This includes input design (forms, login page) and output design (reports). This whole part contributes 18% to the total project mark, and the prototype is the most important piece.

Learning Outcomes

  • Analyze and define system requirements.
  • Apply structured methods for planning, designing, and implementing systems.
  • Design intuitive inputs, outputs, and user interfaces.
  • Develop a functional database application.
  • Solve practical information system challenges.

TBA

Pair-programming exercise

Pair programming is when two people work together on the same code at the same time. One person is the Driver – the one who types. The other is the Navigator – the one who checks for mistakes and thinks ahead. Both people must switch roles often so that no one stays as Driver the whole time.

The two students will work online using VS Code with Live Share so they can edit and see the same code together in real time. They will talk to each other using Webex or any online meeting software. The whole session must be recorded with both cameras turned on, showing both faces and the computer screen. The video is just to show how they worked together, not to make a fancy presentation.

The pair needs to choose a two-hour time slot for the session. They can split it into smaller parts if needed, but the total time cannot be more than two hours. It is recommended that each student tries the exercise alone first so that both come prepared and can help each other better.

Exercise 1 : Introduction to Classes and ObjectsIn progress

This exercise required us to do pair programming in C++. We built a class for a subject with its name, code, and score. Then we added constructors, getters, setters, and methods to calculate the grade, grade point, and total points. The whole coding session was recorded, and we made sure to switch roles between Driver and Navigator. The video was uploaded and shared based on the given instructions.

Project

Object-Oriented Programming Game Project : Squish It !

The main purpose of this project is for our group to develop a 2D game using C++ and a graphics library called WinBGI. Even though we are making a game, the actual goal is to show that we understand Object-Oriented Programming concepts. This includes encapsulation, array of objects, association (both composition and aggregation), inheritance, and polymorphism. We are working in a group of four, and the project is divided into four phases: Project Proposal, Problem Analysis and Design, Interim Progress, and Project Finale. Each phase has different submissions like presentations, reports, videos, and peer assessments. The total weightage for this project is 25% of our final grade.

Project Deliverables 1 : Project Proposal Completed

In Deliverable 1, our group needs to prepare a presentation about our game project. We have to present our game idea including the title, synopsis, mission, and existing games that inspired us. We also need to create a storyboard with at least three scenes showing different gameplay moments like earning points or losing lives. Each group presents face-to-face within 15 minutes and all members must participate. We submit the presentation slides as a group, and each member submits a peer and self assessment form individually. This deliverable is worth 6% of our final grade.

Project Deliverables 2 : Problem Analysis and Design In progress

In Deliverable 2, we need to analyze our game project using OOP. We have to record a group brainstorming session where we identify objects, classes, attributes, methods, and class relationships (association and inheritance) with justification. Then we need to create a UML class diagram using draw.io. We submit three things: the video on YouTube, a PDF report, and an individual peer assessment. This is worth 6% of our grade.

Learning Outcomes

  • Understand the principles of object-oriented programming.
  • Apply encapsulation, association, and inheritance in programming.
  • Develop problem-solving strategies using the object-oriented approach.
  • Implement OOP concepts in C++ to create functional programs.
  • Solve real-world problems through object-oriented solutions.

SECV2113 - Human Computer Interaction

Credit Hours : 3

Lecturer : Dr. Nor Anita Fairos binti Ismail

Section : 02

Course Description

This course introduces human-computer interaction theories and design processes, with a focus on applied user experience (UX) design. It explores an iterative, evaluation-centered UX lifecycle, covering usability, usefulness, and emotional impact. Students engage in activities such as contextual inquiry, requirements analysis, design thinking, ideation, prototyping, and evaluation to create effective and user-centered designs.

Project

Submission 1 - Project ProposalCompleted

This project phase focuses on analyzing the problem space before designing an interactive system. Three usability and user experience problems from existing systems were identified. An interactive solution was then proposed and clearly linked to one of the United Nations' 17 Sustainable Development Goals. Three distinct target user groups who would benefit from the proposed solution were also defined. For our group, the proposed solution is PureCycle, a household waste management mobile application.

This assignment demonstrates the importance of understanding why and how to design something before implementation begins. A key lesson from this phase is that clearly defining the problem space can save significant time, effort, and resources later in the design process. Good design starts not with features, but with a clear understanding of real problems and real users.

Submission 2 - Establishing RequirementsCompleted

This project phase focuses on user needs identification and requirements elicitation for an interactive system. Three user personas were developed, think-aloud observations were conducted with real users, and nine Hierarchical Task Analyses (HTAs) were produced. Based on the findings, functional and non-functional design requirements were derived to improve usability.

This phase contributes 10% toward the overall project grade.

This assignment demonstrates how to move from a problem space to concrete design requirements. Usability issues in existing systems were identified and linked to the UN Sustainable Development Goals. A key lesson from this phase is that good design begins with understanding real people rather than assumptions.

Learning Outcomes

  • Understand fundamental theories of human-computer interaction.
  • Understand fundamental theories of human-computer interaction.
  • Conduct contextual inquiry and analyze user requirements.
  • Apply design thinking, ideation, and conceptual design techniques.
  • Develop and evaluate prototypes using an iterative UX lifecycle.
  • Design user-centered solutions with practical considerations.
